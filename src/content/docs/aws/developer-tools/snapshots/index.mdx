LocalStack is designed to be ephemeral by default, meaning all state is lost when the container stops. The _Snapshot_ feature provides tools to persist, reuse, and share the state of your LocalStack instance across sessions or teams. This is useful for preloading test data, debugging workflows, or collaborating with teammates.

<div style="padding: 1em 0;">
  <img src="/images/aws/snapshot-lifecycle-overview.png" alt="Overview of the LocalStack snapshot lifecycle" width="75%" style="margin: 0 auto;" />
</div>

Snapshots enhance your development workflow in the following ways:

* **Faster loading** - Snapshots can be loaded into your instance within a few seconds. Use this to avoid lengthy redeploys of your infrastructure as code, such as Terraform or CDK, each time the emulator is started.

* **Team sharing** - Use a repository, such as _Cloud Pods_, to share snapshots amongst your team. Snapshots provide a curated set of resources for team members to use as a starting point for their work.

* **Automatic durability** - Enable the _Persistence_ feature to gain the same durability semantics you expect from the AWS cloud. A snapshot is taken automatically when the instance is shut down, or at user-defined periods during operation, then reloaded when the instance is restarted. 

* **Application Preview** - During the code review process, sharing a snapshot allows reviewers to see the software in action, without deploying it for themselves.

* **Debugging failures** - Save the state of an instance after a failure has occurred, allowing debugging at a later time or by a different team member.
